# FOTEK NT-48L-RS 手冊確認清單

查閱 FOTEK 原廠手冊時要確認的項目。以下依一般 Modbus 溫控器手冊結構整理，
實際欄位以原廠手冊為準；某項該型號沒有，直接註記「無此功能」也是有效答案。

分工前提：Modbus 通訊由 Arduino 端負責，本專案（瀏覽器端）透過 Web Serial
以 [PROTOCOL.md](./PROTOCOL.md) 的文字協定與 Arduino 溝通。
因此 A、B 兩節主要給 Arduino 工程師，C～E 節的答案會影響儀表板顯示。

---

## A. 通訊基本設定

| # | 確認項目 | 為什麼重要 | 答案 |
|---|---|---|---|
| A1 | 通訊協定是 Modbus RTU 還是 ASCII，是否可切換 | 決定 Arduino 用哪個函式庫 | |
| A2 | 支援的 baud rate 選項與出廠預設 | 四台要設成一致 | |
| A3 | Data bits / Parity / Stop bits（8-N-1？7-E-1？） | 設錯完全收不到 | |
| A4 | 站號（Address）合法範圍與面板設定路徑 | 四台要設 1～4 且不可重複 | |
| A5 | 是否有通訊寫入鎖參數（LCK / LOCK 之類） | 最常見的坑：讀得到但寫不進去 | |
| A6 | 是否有 response delay（回應延遲）參數 | 影響輪詢週期能壓到多快 | |
| A7 | RS-485 端子 A/B（或 D+/D−）標示與接法 | 接反不會壞但完全不通 | |
| A8 | 是否需終端電阻、建議阻值 | 四台串在同一條匯流排時 | |

## B. 暫存器位址表

每一項都要拿到「位址 + 功能碼 + 資料型別 + 讀寫權限」四件事。

> 欄位名稱已改依 `PROTOCOL.md`（README.txt / xlsx 版本，2026-08-14 更新，見 `CHANGELOG.md`）。

| # | 功能 | PROTOCOL.md 欄位 | 需確認 | 答案 |
|---|---|---|---|---|
| B1 | PV 目前溫度 | `PV` | 位址、功能碼（03 或 04）、signed/unsigned | |
| B2 | SV 設定溫度 | `SV` | 位址、讀寫、寫入功能碼（06 或 16） | |
| B3 | 輸出百分比 | `UN`（讀）/ `NUN`（手動輸出寫入） | 位址、是否可寫、解析度 | |
| B4 | Run/Stop | `ON_OFF` | 位址、是 coil（01/05）還是 register（03/06） | |
| B5 | AT 自動調諧 | `AT` | 位址、寫 1 啟動後是否會自動歸 0 | |
| B6 | Alarm 1 / Alarm 2 狀態 | `STATUS` bit2/bit3（見 PROTOCOL.md 第 22 項） | 位址、分開兩個還是一個 bit 欄位——韌體端已答：`STATUS` 是單一 Bit Mask 暫存器 | 已由 xlsx 確認是單一 Bit Mask |
| B7 | P / I / D | `P` `I` `D` | 三個位址、單位（P 是比例帶% 還是增益？I/D 是秒還是分？） | I/D 已由 xlsx 確認是秒 |
| B8 | 控制模式（自動/手動） | `M_A` | 位址、值定義 | 已由 xlsx 確認：0=AUTO,1=MANUAL |
| B9 | 上述暫存器是否位址連續 | — | 連續的話一次讀取就能拿全部，四台輪詢會快很多 | |

## C. 資料換算與語意

這幾題答錯，畫面會顯示錯的數字，但程式不會報錯。

| # | 確認項目 | 為什麼重要 | 答案 |
|---|---|---|---|
| C1 | 溫度值是否帶隱含小數（80.0 °C 傳回 `800`？） | 差十倍。建議在 Arduino 換算好，PC 端只收人類可讀值 | |
| C2 | 小數位數是否隨面板 DP 參數變動 | 若會動，Arduino 得先讀 DP 才能正確換算 | |
| C3 | 負溫度如何表示（16-bit 二補數？） | 室溫以上用不到，但感測器異常時會出現 | |
| C4 | 輸出百分比的真正語意：手動輸出命令、輸出上限、還是 PID 的唯讀回報值 | 現行 `OUT,<id>,<value>` 假設是「手動模式下可寫」。若其實唯讀，這條指令會靜默無效 | |
| C5 | 若 C4 可寫，寫入前是否必須先切到手動模式 | 是的話 `OUT` 指令要連帶切模式，或 UI 要加模式切換 | |
| C6 | 輸出讀值範圍是 0～100 還是 0～1000（0.1% 解析） | 直接影響顯示 | |
| C7 | 是否另有獨立的「輸出上限」參數 | 若有，100% 可能不是滿載，UI 要標示清楚 | |
| C8 | SV 可寫範圍上下限、是否受感測器型別限制 | 前端驗證的依據 | |

## D. 寫入行為與壽命

| # | 確認項目 | 為什麼重要 | 答案 |
|---|---|---|---|
| D1 | 寫入 SV/PID 是否寫進 EEPROM？有無寫入次數壽命限制 | 若有（常見 10 萬次），不能做「拖曳滑桿即時寫入」，必須放開才送出。直接影響 UI 設計 | |
| D2 | 是否有不寫 EEPROM 的 RAM 暫存器可用 | 有的話頻繁調整走這個 | |
| D3 | 寫入後要等多久才能再讀（write cycle time） | Arduino 的排隊間隔 | |
| D4 | 寫入超出範圍時的回應（exception code？靜默忽略？） | 決定 Arduino 能不能回報失敗給 PC | |
| D5 | 寫入成功後 read-back 是否立即反映新值 | 若有延遲，「送出後多久算失敗」要放寬 | |

## E. 異常與診斷值

| # | 確認項目 | 為什麼重要 | 答案 |
|---|---|---|---|
| E1 | 感測器斷線時 PV 回傳什麼值 | 常見是特定極值（如 32767）。不確認的話畫面會把它當真實溫度顯示 | |
| E2 | 超量程（過高/過低）的回傳值 | 同上 | |
| E3 | 是否有獨立的錯誤狀態暫存器 | 有的話比猜 PV 特殊值可靠 | |
| E4 | Alarm 1 / Alarm 2 的觸發條件由哪些參數決定 | 決定 UI 該顯示成什麼（超溫？偏差？） | |
| E5 | Alarm 是否需手動復歸 | 影響 UI 要不要做「確認警報」按鈕 | |

## F. 手冊查不到，要問電機／控制人員

| # | 確認項目 | 為什麼重要 |
|---|---|---|
| F1 | 通訊中斷時，溫控器維持目前輸出還是停止 | 若維持輸出，PC 斷線時燈管還在加熱，UI 不能顯示成「已停止」 |
| F2 | 現場有沒有獨立的硬體超溫保護／急停 | 沒有的話，這套系統的定位要重新談 |
| F3 | 四台是否共用一條 RS-485 匯流排 | 決定單台故障會不會拖垮全部 |
| F4 | 四台的站號實際設定值與燈管實體位置對照 | 避免控制錯台；建議實體貼標籤 |
| F5 | 是否允許遠端 Run/Stop 與 AT | AT 執行中溫度會大幅振盪，產線運行時未必能做 |

| G6 | 廣播 `id=0` 的實作方式 | README.txt 的 SET_MAIN/SET_SET/SET_ADVANCED 都是用站號（1~255）定址，沒有再提到廣播位址 0 這件事，需要再跟韌體工程師確認廣播是否還支援 |
| G7 | **`SET_ADVANCED` 的 `NUN` 參數不管送什麼值都被拒絕（`SET_ERROR(PARAM:NUN,CODE:2)`）** | 2026-08-14 現場實測：指令格式正確（7 參數，跟 README.txt 一致），`RS`/`BPS`/`BIT`/`controlMode` 都能正常送出並被接受，唯獨 `NUN` 這個欄位——包含文件建議的哨兵值 `-1`，以及手動模式下想設定的實際輸出值（例如 10、100）——**全部**收到 `SET_ERROR(PARAM:NUN,CODE:2)`，沒有一次成功過（前端一度誤判「自動模式送 -1 有成功」，後來發現是前端 read-back 判斷邏輯本身的 bug，排除掉那個因素後結果是穩定、可重現的失敗）。需要韌體工程師從韌體端確認：`CODE:2` 判斷 `NUN` 合法性的條件是什麼？連 `-1` 都不接受是預期行為，還是這段驗證邏輯本身有問題／還沒做完？在確認前，「手動輸出量」功能視為不可用，見 `CHANGELOG.md` 相關紀錄 |
| G8 | `SET_MAIN`/`SET_SET`/`SET_ADVANCED` 送出去的站號參數，跟 PC 端本地的燈管 id（1~4）是不是恆等？ | 目前前端直接拿本地 id 當站號送出。`lampState.ts` 已經做了站號↔本地 id 的路由表（`setStation`），理論上可以應付兩者不同的情況，但這個對照關係本身還沒跟韌體工程師核對過——如果之後在進階設定把某支燈管的設定站號改成別的值，要確認韌體端真的是照這個站號定址，不是仍然認本地 id |

## 優先順序

時間有限時先解這四題：**A5、C1、C4、D1**。答錯會導致「程式看起來對、實際行為錯」，是最難除錯的類型。
F1 屬安全相關，要獨立問到書面答覆。G1 現在就可以先跟 Arduino 工程師講，不用等手冊。
**G7 是目前唯一確定壞掉、擋住功能的項目**（手動輸出量完全無法設定），建議跟 A5、C1、C4、D1 一起優先問。
